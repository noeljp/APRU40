🌐 Zone IoT - Capteurs et Équipements
📡 Nœuds Capteurs ESP32
  • 30× ESP32-POE-ISO
  • ADC: ADS7128 (12-bit) + ADS1119 (16-bit)
  • Mesures: Température, Pression, Courant
  • Acquisition: 5s
  • Transmission: 10s via ESP-NOW
📷 Scanner Zebra DS2278
  • Bluetooth Classic SPP
  • Codes-barres 1D/2D + QR
  • Portée: 10-30m
  • Sécurité: PIN + Whitelist MAC
  • Pairing: Authentification sécurisée
🔐 Sécurité Locale
  • Tamper Switch physique
  • Auto-erase NVS si ouverture
  • Flash Encryption (AES-256)
  • Secure Boot V2
  • Détection intrusion physique

🔒 Protection Niveau IoT

  • Chiffrement ESP-NOW: AES-256-CBC + IV aléatoire
  • Authentification: HMAC-SHA256
  • Anti-replay: Compteur incrémental par nœud
  • Whitelist MAC: Contrôle sources autorisées
  • Bluetooth: PIN aléatoire 6 chiffres + Whitelist stricte

🌉 Bridge - Broker MQTTS (TLS 1.3)
🔄 Broker MQTTS
  • Protocole: MQTT over TLS 1.3
  • Port: 8883 (MQTTS standard)
  • Authentification: Certificats X.509
  • Topics par nœud: apru40/node/{id}/data
  • QoS: Niveau 1 (at least once)

🔐 Sécurité Bridge
  • TLS 1.3 (Perfect Forward Secrecy)
  • Certificats CA internes
  • Mutual TLS (mTLS) authentification
  • Isolation réseau BMN ↔ OI
  • Logs d'audit complets

🔒 Protection Niveau Bridge

  • Chiffrement TLS 1.3: ChaCha20-Poly1305 ou AES-256-GCM
  • Authentification mutuelle: Client + Server certificates
  • Révocation: CRL (Certificate Revocation List)
  • Segmentation réseau: Firewall entre BMN et OI
  • IDS/IPS: Détection intrusion sur flux MQTTS

📊 Types de Flux de Données

📈 Flux Données (Data)

  • Source: Capteurs IoT → Gateway
  • Fréquence: 10 secondes
  • Contenu: Mesures ADC (température, pression, courant)
  • Format: JSON chiffré AES-256
  • Destination: Broker MQTTS → BMN/OI
  • Sécurité: ESP-NOW + MQTTS (double chiffrement)

⚙️ Flux Configuration (Config)

  • Source: Interface Admin → Broker → Gateway → IoT
  • Fréquence: À la demande
  • Contenu: Paramètres capteurs, périodes acquisition
  • Format: MQTT publish sur topics /config
  • Authentification: Certificats TLS client
  • Validation: Signature numérique requise

🔄 Flux Mises à Jour (OTA)

  • Source: Serveur OTA → Broker → Gateway → IoT
  • Fréquence: Maintenance planifiée
  • Contenu: Firmware ESP32 signé
  • Signature: RSA-3072 ou ECDSA
  • Intégrité: Hash SHA-256 vérifié
  • Rollback: Automatique si échec
🔐 Résumé Stratégie Sécurité Globale

🛡️ Défense en Profondeur

  • Couche 1: Tamper physique + Flash Encryption
  • Couche 2: ESP-NOW AES-256 + HMAC
  • Couche 3: Bluetooth PIN + Whitelist
  • Couche 4: Passerelle IT validation
  • Couche 5: MQTTS TLS 1.3
  • Couche 6: Firewall BMN ↔ OI

👁️ Détection et Réponse

  • Monitoring: Tamper switches temps réel
  • Statistiques: Attaques HMAC, replay détectées
  • Alertes: Notifications ESP-NOW/MQTT instantanées
  • Logs: Audit complet tous flux MQTTS
  • Auto-erase: NVS effacé si intrusion
  • Conformité: NIS2 Directive (EU) 2022/2555

🔑 Gestion Clés et Certificats

  • AES-256: Clés uniques par déploiement
  • HMAC-SHA256: Clés distinctes authentification
  • TLS 1.3: Certificats X.509 CA interne
  • Rotation: Protocole renouvellement clés
  • Storage: eFuse (future) pour clés critiques
  • Révocation: CRL pour certificats compromis
